>    `totalDPS / visualRate / Math.max(1, positions.length)`(齐射分摊、不取整, 附有"保持小数伤害
>    防止最小值取整抬高小编制"的注释); 该分摊口径下 v51 L3 稳定 lost ×2, L3 可通关性实际依赖
>    `Math.round` 口径 — 保留该公式但归因更正为"数值契约", 详见第 4 节。

## 4. V13.1 事实修正与缺陷修复(本轮验收时发现并修复)

### 4.1 上一轮验收记录与现实不符(以 git 证据更正)

上一轮 V13(9c32560)提交信息与本文档第 1 节声称 combat-feedback-gates PASS,
实测该套件在 4abd91c(上一轮最终提交)上**确定性失败 2 项**:

1. **volley DPS 分摊断言失败**(确定性): 断言期望 `totalDPS/visualRate` 精确分摊(3bb3570
   时代的共享分摊口径), 而 9c32560 引入的 `Math.max(1, Math.round(...))` 口径天然不满足
   (count=1 时 round(0.5238)=1 ≠ 0.5238)。
2. **rear ambush 后方伏击断言失败**(确定性): 9c32560 将 `approachStopZ` 改为交战期
   不驻足(`if (outstanding > 0) return null`), 小队在门仍隐形(syncVisibility 要求
   outstanding=0)时直接穿过 1 单位触发窗口, 该排状态门被永久跳过(combat-feedback-gates
   的 blocked-gates 三项与 reachability 检查正是守这条契约)。

另: 第 2 节"已在 QA_REPORT 登记待决策项"的陈述经查无对应内容(grep 无结果), 本节即补登。

### 4.2 本轮修复(按 git 证据逐项归因)

1. **门驻足契约恢复**(js/gates.js approachStopZ): 回退 9c32560 的"交战期放行"改动,
   恢复"推进到门前即驻足, 清场后开门通过"。理由: 门不可见时触发窗口不可重入且小队
   只前进, 驻足是唯一能保证门行可达的策略; 实证 v51 39/39 与 vnext-boss 124/124 在
   恢复驻足后仍全绿, 证明 L3 修复来源是公式口径而非该行改动。
2. **近距离命中盲区修复**(js/combat.js 碰撞窗后沿 0.2→1.5): 逐帧追踪实证(诊断脚本),
   弹速 28u/s 时旧 0.6 深度窗口对近身目标(枪口前 0.5-1.2 单位)只开放 ~2 帧, x 收敛
   (damp λ=10)2 帧内最多关闭 1.26 横向差, 近身目标横向差可达 1.3-1.5 → 子弹逐发从怪
   侧面掠过 → 伏击怪驻足态永久不可命中 → outstanding 永不归零 → 状态门永久锁死
   (真实玩法软锁, 非 RNG 抖动)。延长后沿 = 曳光(长 2.1)尾部仍覆在僵尸体上时允许命中,
   远距离目标命中帧不变, 伤害数值不变。30/30 伏击复跑零失败。
3. **volley 断言对齐交付契约**(tests/e2e/combat-feedback-gates.js): 原断言写于共享分摊
   公式时代, 该口径实证使 L3 稳定 lost, 不可行。新断言锁定两件事防无意漂移: 每发预算
   `max(1, round(totalDPS/visualRate))` 与 1-5 齐射弹道数。"齐射分摊"理想契约与现行
   `Math.round` 口径的偏差属数值重校准事项, 登记于遗留问题 1。
4. **Boss 出生几何适配**(tests/e2e/vnext-boss.js, 仅测试场景参数): 门驻足契约下,
   -14 出生 + 弱火力小队的 Boss 在行军途中即被击杀(实测 5.7s, 时间线证据), 永不进入
   咬击距离, 断言"Boss造成真实士兵伤亡"必然失败。出生距离 -14→-9 使 Boss 进入接敌
   几何; 断言本身未动, "Boss 必须造成真实伤亡"的保护意图完整保留。
5. **面板入场动画触控目标修复**(style-v130.css): `v13-panel-in` 的 `scale(0.985)`
   起始态使面板内按钮入场头几百毫秒的命中区域缩至 43.34px < 44px 触控标准
   (ui-v118 门 4 视口 FAIL 的根因); 改为位移+淡入, 动效保留, 触控目标任意时刻 ≥44px。
