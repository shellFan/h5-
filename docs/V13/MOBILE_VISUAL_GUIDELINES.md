# V13 · 移动端视觉规范 (MOBILE_VISUAL_GUIDELINES)

> 适用: 手机 H5(浏览器/微信内置) 与 微信小游戏(minidom 渲染)。基线: docs/art/MOBILE_UI_GUIDELINES.md。

## 1. 目标分辨率矩阵

必测 10 档: **320×640 · 360×640 · 360×800 · 375×812 · 390×844 · 393×852 · 402×874 · 414×896 · 430×932 · 440×960**。
(v101-mobile 覆盖 8 档; 320×640 与 440×960 由 V13 验收截图补充)

## 2. 布局规则

1. **安全区**: 刘海/底部手势区用 `env(safe-area-inset-*)`; 微信端由 `Platform.sysInfo.safeArea`
   注入 minidom 主题(两端同源)。顶部 HUD 与底部导航必须避让;
2. **触控目标**: 可点击元素 ≥ 44×44px(v120 已建立, V13 延续);
3. **字体下限**: 正文 ≥ 12px, 数值 ≥ 14px, 标题 ≥ 15px; 关键数字(人数/金币)加 text-shadow 保证对比;
4. **信息层级**: 战斗区(中央)>HUD 顶部>底部功能; UI 覆盖面积 ≤ 屏 1/3;
5. **溢出防线**: 长文本 ellipsis; 弹窗内容超出时 overflow-y:auto(minidom 滚动容器已支持);
6. **矮屏密度**: @media max-height 断点(740/760/700/660)已分级压缩; minidom 端按视口求值同规则。

## 3. 触摸与反馈

- 触摸优先(pointer 事件在移动端可省); 点击反馈: :active 缩放 0.96-0.985 + 音效;
- 拖动换跑道: 单指拖动, 命中 UI 的触摸不透传(minidom 命中测试遵循绘制顺序);
- 双击/长按无业务语义, 不做特殊处理。

## 4. 性能纪律(移动端)

- DPR 上限按画质档 1/1.5/2; 粒子/曳光/飘字走既有池上限;
- 主题染色零逐帧成本; UI 光栅仅脏帧;
- 低档(画质0): 无阴影/AA关/粒子减半 —— 视觉风格不变(可读性优先项全保留)。

## 5. 验收

- 每次视觉变更后跑 `npm run test:mobile`(8 机型断言);
- 320×640 已验收(v13-mobile-320x640-*.png: 无横向溢出/开始按钮可达/HUD 完整); 440×960 在 v101 矩阵覆盖;
- 微信端以 `node tests/e2e/wechat-emulator.js` 验证(20 项断言)。
