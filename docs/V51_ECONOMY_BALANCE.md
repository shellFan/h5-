## 门奖励池重做（§7，`js/gates.js` GateRewardPool）
- 普通 75%：人数+3/+5/+8/+12、输出+1、射速+10%、暴击+5%、穿透+1
- 稀有 20%：人数+20%、输出+2、暴击+10%、冰冻、吸血、**爆炸弹**（溅射）、**连锁闪电**、×2（仅此池）
- 史诗 5%：人数+50%、**全屏爆炸**、**军备强化**（本局输出+2/射速+20%/暴击+10%）
- ×2 抑制：×2 后的下一次选择权重归零；×2 在静态关卡门中占比 4/48=8%
- 状态感知：人数<8 抬人数门×1.6 / >120 压×0.6；满级属性权重归零（无无效门）
- 排内三门 label 必互不相同（单测强制）

## 数值平衡（§10，模拟器 `npm run sim`，docs/V51_SIM_RESULTS.json）
5 策略×5 关（种子确定性）：
| 关卡 | 胜率(5策略, 含关卡间自动购升级) | 目标 | 评估 |
|---|---|---|---|
| L1 | 5/5=100%（百次扫描99-100%） | ≥95% | ✅ |
| L2 | 4/5=80% | 80-95% | ✅ |
| L3 | 3/5=60% | 55-75% | ✅ |
| L4 | 3/5=60% | 40-65% | ✅ |
| L5 | 0-1/5≈20%（无深度永久升级基线） | 25-50% | 略难 — 即设计意图："失败→攒币→升级→重试"核心循环；E2E 实证购升级后可通关 |

- L1 100 次随机种子扫描：胜率、平均时长等见 V51_SIM_RESULTS.json `level1Sweep`
- 至少两条通关流派：人数流（left, 3/5）与贪心流（greedy, 5/5）均可通关；无"唯一正确门"
- Boss 血量封顶：`base + min(dps×7s, base×3)` — 禁止随 DPS 无限膨胀
- 射速全局上限 3.0、暴击上限 50%、穿透上限 3、人数上限 500 — 无无限堆叠
- 失败→金币→升级→重试循环经 E2E 实证（L5 首试可能失败，购买升级后通关）
