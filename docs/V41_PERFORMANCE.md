日期：2026-11-12。原始逐项数据：[v41-performance.json](v41-performance.json)。复现：

```powershell
node tools/v41-performance.js
```

## 环境与方法

系统 Edge 157，Windows，ANGLE (Intel, Intel(R) Arc(TM) 130T GPU (16GB) (0x00007D51) Direct3D11 vs_5_0 ps_5_0, D3D11)；浏览器报告 14 个逻辑线程。采用硬件 ANGLE/D3D11 渲染，本轮不是 SwiftShader。四种 viewport、deviceScaleFactor=1、headless 桌面浏览器；**不是手机真机成绩**。刷新节奏约60Hz，未禁用 VSync/rAF 调度；实际帧间隔会受浏览器调度影响。

每个尺寸/人数新建浏览器 context，固定随机种子，启动真实 Game，清除敌人/门/节奏计划以隔离战斗波动；小队仍真实前进并自动射击。预热2000ms，采样3000ms，使用原始 requestAnimationFrame 时间戳，未使用游戏中被 dt 上限钳制的 FPS。不是满场 Boss/特效极限战斗基准。

下表 DrawCall/三角形来自 renderer.info，包含道路/建筑/弹道及已启用的阴影，不等同于纯士兵成本。模型载入耗时含两份本地 GLB 的请求、解析和贴图解码；不是公网首次加载时间。

## 角色渲染成本

完整角色12,454三角形，LOD3,730。100人完整角色约1,245,400三角形；500人LOD约1,865,000三角形。两组五部件实例网格共用一个 PBR 材质和两张实际纹理；只绘制活动组，角色基础成本5次调用，阴影另算。死亡残影复用同组16个槽位。>100人启用LOD和30Hz动作周期采样；>64人关闭角色动态投影。

## 内存趋势

先预热两个模型组及场景资源，再暂停无关模拟，执行10次1→500→1人数变化并真正更新/渲染实例。该测试隔离角色增长重置的资源保留；不代表长时间完整战斗内存审计。

- 预热后JS堆：10791434 → 10799850 字节，差 8416 字节。
- renderer.info几何数量：182 → 182；纹理数量：5 → 5，10次重置无增长。
- 显式GC暴露：可用（启动参数 --expose-gc）；GC基线到末次快照差 8416 字节，小于5MiB开发门槛。
- performance.memory 是 Chromium 的粗粒度统计，部分相邻快照相同；短时无持续增长不等于证明永远无泄漏。

## 比较与剩余验证

本轮与旧版的视觉对比见视觉报告。旧V4性能报告的环境、场景及FPS算法不同，因此未将其数值计算为性能提升比例。此次没有声称模型细节增加后性能提升。

仍需 iOS Safari、Android Chrome、高DPR、微信/抖音容器、发热降频和长时完整战斗补测。旧道路/建筑及每发Sprite弹道仍占多数DrawCall，后续若优化应以真机实测决定。原始数据生成时间：2026-11-12T13:32:00.929Z。运行时实现对应 a368f52，之后只新增验证工具/文档。
