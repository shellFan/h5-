# 深蓝金色 UI · 实装与验证

日期：2026-11-21。基于 `3bb3570`，依据用户确认的两张概念图实施界面层改版。

## 已直接接入游戏

- 首页、战斗 HUD、暂停/结算与现有辅助页面使用深蓝面板、金色主操作和统一边框。
- 首页标题改为可读的暖金色；战斗人数只显示于固定属性条，避免旧投影气泡遮住 HUD。
- 补兵通知保留真实来源/增量与原合并规则，使用薄荷绿通知样式。
- 军械库新增当前武器展示区，八种透明插图与双列卡片；原切换、升级、进化及解锁操作继续使用原处理函数。
- 战绩榜明确标注“本机战绩榜”，前三名只取真实记录；零、一、二、三和二十条记录均有对应布局。
- 前三名的分数、结果、职业和日期直接展示，击杀/最大人数/连杀/用时可展开查看。
- 新样式和插图已进入 H5 构建，浏览器加载不依赖外部 CDN。

## 验证结果

| 检查 | 结果 |
|---|---|
| 新 UI 回归 `node tests/e2e/ui-v118.js` | 7 项通过，含真实 alpha、八个图集格、真实切换/扣费升级及四种屏幕适配 |
| 单元测试 | 92/92 |
| 主流程 E2E | 29/29 |
| 本机战绩/加载生命周期 | 16/16 |
| 武器升级/进化/词条 | 14/14 |
| 战斗补员与漏门回归 | 11/11 |
| 移动端旧测试的功能/布局检查 | 27 项通过 |
| H5 构建与产物浏览器检查 | 通过 |

移动端旧测试的两项压力性能门槛仍未通过：单独运行约 33 fps、平均 10.57ms（目标分别为 ≥45 fps、≤10ms）。为判断是否来自 UI，本次用相同资源、相同随机种子、相同场景、DPR2、4×CPU 节流、全模型加载完成且停用额外自动循环进行了基线对比：旧 UI 约 42.3 fps / 15.24ms，新 UI 约 46.2 fps / 12.83ms。该对比没有显示 UI 性能回退，但不代表旧压力测试的全部门槛已达标，也不作为手机实机帧率承诺。

广泛检查中的 V8.0 套件有三项挑战结算断言失败。以 `HEAD` 原版 HTML 和 UI 脚本注入同一测试复核，也复现了完全相同的“挑战模式失败判定、挑战结算标记、失败原因显示得分”三项失败（34 通过 / 3 失败）。本轮不修改挑战结算玩法，不把它们列为通过。

代码独立复查未发现剩余的重要运行时/UI 数据问题。复查指出截图需要在最后 CSS 修改后重采集；上述截图已重新生成并检查。

## 范围与资产

程序改动仅在界面模板、样式引用、UI 构建打包和验证脚本。没有修改伤害、血量、出怪、选门规则、排行榜评分或持久化格式。

`assets/ui-v118/weapon-atlas.png` 是界面插图，不替换士兵持枪 GLB。素材来源及提示词见该目录的 README。概念图里的新怪物、三维场景和完整战斗特效仍是独立资产任务，不能把本次 UI 改版当作这些 3D 内容已全部完成。

保留用户已有的头像、士兵模型、贴图与建模脚本改动，不将其纳入本次 UI 提交。
