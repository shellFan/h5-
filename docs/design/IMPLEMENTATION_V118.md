# 深蓝金色 UI · 实装与验证

日期：2026-11-21。最初基于 `3bb3570` 制作，交付前已整合远端五个更新至 `25e1fae`，保留 V12 视觉、微信适配、存储设置和挑战修复，再应用用户确认的深蓝金色界面。

## 已直接接入游戏

- 首页、战斗 HUD、暂停/结算与现有辅助页面使用深蓝面板、金色主操作和统一边框。
- 首页标题改为可读的暖金色；战斗人数只显示于固定属性条，避免旧投影气泡遮住 HUD。
- 补兵通知保留真实来源/增量与原合并规则，使用薄荷绿通知样式。
- 军械库新增当前武器展示区，八种透明插图与双列卡片；原切换、升级、进化及解锁操作继续使用原处理函数。
- 战绩榜明确标注“本机战绩榜”，前三名只取真实记录；零、一、二、三和二十条记录均有对应布局。
- 前三名的分数、结果、职业和日期直接展示，击杀/最大人数/连杀/用时可展开查看。
- 新样式和插图已进入 H5 构建，浏览器加载不依赖外部 CDN。

| H5 构建与产物浏览器检查 | 通过 |
| 微信构建与模拟器冒烟 | 20/20，含9处图集加载、8个单格裁切及共享一张图片解码 |

整合远端更新前，移动端旧测试的两项压力门槛未通过：单独运行约 33 fps、平均 10.57ms（目标分别为 ≥45 fps、≤10ms）。当时用相同资源/随机种子/场景、DPR2、4×CPU 节流、全模型加载完成且停用额外自动循环对比：旧 UI 约 42.3 fps / 15.24ms，新 UI 约 46.2 fps / 12.83ms。这是原 `3bb3570` 阶段的历史诊断，不代表最终整合版本的性能承诺。

整合 V12 后再次单独执行移动测试，结果为 28 通过 / 1 失败：平均帧耗约8ms达标，4×CPU/DPR2 压力帧率约35.7未达45门槛。该项保留为未通过，不宣称所有压力指标已通过。

原 `3bb3570` 的 V8.0 套件还存在三项挑战结算失败；旧 HTML/UI 注入也同样复现。远端的 `693c819` 已修复相关集成问题，本次完整保留，最终 V8.0 套件 37/37 通过。本次 UI 没有自行改写挑战结算玩法。

代码独立复查未发现剩余的重要运行时/UI 数据问题。复查指出截图需要在最后 CSS 修改后重采集；上述截图已重新生成并检查。

## 范围与资产

程序改动在界面模板、样式引用、UI 构建打包、微信 UI 画布适配和验证脚本。没有修改伤害、血量、出怪、选门规则、排行榜评分或持久化格式。

微信图集放入主包 `ui-art/`，避免已有 assets 分包超过 4MB；最终主包约 2.80MB，assets 分包约 3.37MB。原生画布通过显式图集坐标裁切，九处插图共享单张已解码图片，并修复动态菜单子节点 ID 查找，使新军械库入口和插图能被找到。模拟器的包内图片 URL 仅在测试宿主中调整，不改变生产图片/GLB 加载机制。模拟器通过不等同真机发布认证。

`assets/ui-v118/weapon-atlas.png` 是界面插图，不替换士兵持枪 GLB。素材来源及提示词见该目录的 README。概念图里的新怪物、三维场景和完整战斗特效仍是独立资产任务，不能把本次 UI 改版当作这些 3D 内容已全部完成。

保留用户已有的头像、士兵模型、贴图与建模脚本改动，不将其纳入本次 UI 提交。
