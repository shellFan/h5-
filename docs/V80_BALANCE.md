# V8.0.1 平衡性报告 — 十关战役调优

> 调优方法: 浏览器内真实战斗模拟 (tools/v80-balance-sim.js), 每关按"自然/富裕"两档养成预算各 N 局, 统计胜率/击杀/用时/最低存活。

## 一、发现的核心 Bug (全部已修复)

1. **CONFIG.BOSS_NAMES 数组未闭合** — L7-L10 关卡定义被吞进 BOSS_NAMES 字面量:
   - `BOSS_NAMES[6..9]` 变成关卡对象 → Boss 血条显示 `[object Object]`。
   - `LEVELS.forEach` 用 `BOSS_STYLES[6..9]=undefined` 覆盖 L7-L10 已写明的 Boss 体格。
   - 修复: BOSS_STYLES/BOSS_NAMES 扩到 10 项, 删除重复块, forEach 尊重已写明 style。

2. **ENEMY_HP_MULTIPLIER 越界** — 数组仅 6 项, L7-L10 (索引 6-9) 取 undefined:
   - `Math.round(refHp × undefined) = NaN`, 而 `hpOverride || cfg.hp` 中 NaN 为 falsy → **静默回退基础血量**。
   - 敌人以 1× 血量生成, 关卡难度完全失控 (无法标定)。
   - 修复: 数组补齐 10 项 + game.js 取值加 `Math.min(levelIndex, len-1)` 越界防御。

3. **武器/科技伤害属性从未生效** — `_weaponStats.dmgMul`、`_techStats.dmgBonus` 只计算不消费:
   - 修复: squad.getDamage() 叠加科技 dmgBonus 与武器 dmgMul; 武器 pierceBonus/chain/slowMul/radius/critBonus 全部接线。

4. **双因子 Boss 血量公式在重构中丢失** — 注释还在, 代码只剩 `hp = base`。
   - 修复: 恢复 `hp = clamp(count×totalDPS×0.5, 关卡值×0.5, 关卡值×12)`。

5. **Boss 战输出饥饿** — 复数敌人时弹道锁定"最近敌人", Boss 被杂兵挡枪, 4500 血 Boss 打出 200s 消耗战。
   - 修复: Boss 存活时全部弹道优先锁定 Boss。实测 45 人小队 Boss 战 ≈ 9s, 与设计意图 (8-12s) 吻合。

6. **L8 全关零人数门** — 三个门行全是 buff/skill, 起始 1 人 + 招募等级撑全场。
   - 修复: 三行门各补人数门 (+25 / +30% / +20), 增设 Boss 前强化行。

## 二、难度杠杆 (实测标定)

| 杠杆 | 结论 |
|---|---|
| 敌人 HP 乘数 | L7-L10 波次编制大 (130-290), HP 乘数 5.0-6.4 实测开局 11s 全灭; 最终取 2.2/2.5/2.8/2.6 |
| 杀伤吞吐上限 | 杀伤速率 = visualRate × volley × 命中率, 与伤害无关 (溢出饱和)。曲线从 ×1.8/上限22 提到 ×2.2/上限30, 齐射 ÷2.6→÷2.3 |
| 小队规模 | 吞吐随人数增长 — 后期关人数门 (+45/+50%/+40%) 是第一难度杠杆 |
| Boss 血量 | 双因子公式使 Boss 战时长与养成解耦 (~9-12s), 关卡 authored 值只作下限锚 |
