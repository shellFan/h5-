## 1. 本项目视觉定位

### 1.1 核心体验

《膨胀小队》是“人数膨胀爽感 + 自动射击清怪”的 3D 卡通休闲游戏。视觉必须让玩家一眼看懂：

1. 我方小队人数正在增长，队伍规模越大越有压迫感。
2. 士兵拿着清晰可辨的枪械，持续朝敌人自动射击。
3. 僵尸潮有数量、有层次、有威胁，命中、受击、死亡反馈清楚。
4. 三选一状态门是每局最重要的视觉决策点。
5. 关卡从城市、工业区到实验设施等环境逐步变化，不能只是同一条路换颜色。

关键词：**精致、明亮、饱满、可爱但不幼稚、军事科幻、蓝金主色、强反馈、移动端清晰**。

### 1.2 视觉基调

- 主色：科技蓝、深海军蓝、冰蓝高光。
- 强调色：金币金、奖励橙、危险红、毒素紫绿。
- 士兵：蓝色阵营，统一识别色；不同职业用肩章、头盔、背包、枪械和局部灯带区分。
- 怪物：以灰绿、腐败黄、暗红为基础，精英和 Boss 使用更鲜明的轮廓与弱点色。
- 材质：PBR/卡通化混合，轮廓清晰，适度描边、边缘光、金属高光；避免塑料球、纯色胶囊和低细节堆叠。
- UI：深蓝半透明玻璃面板、清晰分层、轻量描边、金色奖励数字、红色危险提示。
- 画面必须保持可读性：特效不能遮住士兵、怪物、门的数值和关键战斗信息。

不要把所有东西都做成蓝色发光。蓝色负责我方与科技 UI，怪物、场景、奖励、危险必须有明确的色彩分区。

## 3. 分模块美术设计要求

### 3.1 UI 系统

先建立一套可复用设计语言，再逐页面落地，禁止每个页面各做各的。

- 字体：标题、数值、正文、辅助说明四级；数字优先使用清晰等宽或数字辨识度高的字体。
- 面板：深蓝半透明底 + 细描边 + 柔和阴影；重要弹窗有明确标题、内容和主/次操作。
- 按钮：主按钮、次按钮、危险按钮、禁用按钮四种状态；按下/悬停/禁用状态一致。
- 图标：统一采用原创 SVG/PNG 或项目许可兼容素材，禁止 emoji 充当最终图标。
- 资源展示：金币、钻石、等级、人数等图标与数字间距统一。
- 动效：短促、克制、可跳过；不使用持续大面积闪烁。
- 所有 UI 必须覆盖 360×640、360×800、375×812、390×844、414×896、430×932、768×1024 等视口，并额外检查刘海屏安全区。

### 3.2 怪物与 Boss

每种怪物先做“剪影识别”，再做细节：

- 普通僵尸：基础威胁，轮廓完整、动作迟缓。
- 快速僵尸：前倾、细长、低重心，具有高速移动感。
- 盾牌僵尸：大型盾牌/护甲，正面防御特征突出。
- 分裂僵尸：身体裂纹、分裂部位和死亡分裂提示明显。
- 远程僵尸：背部/手部远程器官或投射物特征清晰。
- 爆炸僵尸：高饱和危险标识、蓄爆/死亡预警，爆炸前必须可读。
- 精英：比普通怪更精致，具备独特护甲、轮廓和受击反馈。
- Boss：每个 Boss 必须有独立主题、体型比例、攻击前摇、弱点部位、阶段变化和专属死亡演出。

约束：
- 不允许仅改变颜色就算一种新怪物。
- 不允许用普通怪放大后冒充 Boss。
- 受击闪白要短暂且限幅；不要全身持续刷白。
- 怪物不能被地面、建筑、特效遮挡到无法辨识。
- 优先复用现有模型工厂、动画与实例化体系；新模型必须提供 LOD 或低端设备降级方案。

### 3.3 地图与背景

以章节为单位设计，不要只按关卡随机换装饰。

建议主题方向（最终需结合现有关卡设定对齐，不能破坏剧情/关卡语义）：

1. 城市失守区：破损街道、废弃车辆、路障、路灯、远处高楼、警示灯。
2. 工业隔离区：管线、集装箱、冷却塔、警戒围栏、蒸汽、危险标志。
3. 生化实验区：实验舱、玻璃管、警报灯、冷色灯带、污染区域。
4. 荒野/污染区：枯树、岩石、塌陷地表、污染雾、远处设施。
5. 终局巢穴：巨大生物结构、孵化囊、脉动光源、Boss 专属地标。

每个章节至少设计：
- 1 张章节主视觉/选关背景。
- 1 套地表/道路材质。
- 1 套远景轮廓。
- 6–10 种可复用环境道具。
- 1 套环境色与灯光配置。
- 1 个章节识别色/标识。
- 进入章节、战斗中、Boss 战、通关结算四个状态的视觉延续。

移动端限制：
- 背景是衬托，不得抢占战场对比度。
- 优先使用低成本几何体、合批、实例化、贴图图集和雾效。
- 避免高透明物体大量叠加、实时阴影泛滥和超大纹理。
- 远景、近景和战斗路径必须有景深层次，但不可影响碰撞/导航逻辑。

### 3.4 枪械与攻击特效

现有武器系统已经存在，重点是让每种武器“看起来、打起来都不同”，不擅自重做武器数值。

| 武器风格 | 视觉语言 | 射击反馈 |
|---|---|---|
| 步枪 | 军用制式、稳定、枪身结构清晰 | 短促枪口焰、连续弹道、轻微后坐 |
| 散弹 | 枪管粗壮、近距离火力感 | 多弹丸扇形、强枪口焰、密集命中火花 |
| 狙击 | 长枪管、瞄准镜、精密感 | 高亮单发弹道、穿透轨迹、弱点命中提示 |
| 机枪/重火力 | 厚重枪身、弹链/散热结构 | 连续火焰、弹壳/热量表现（注意性能） |
| 火焰类 | 喷射器、燃料罐、耐热结构 | 连续火焰束、燃烧区域、持续伤害视觉提示 |

统一特效分层：
1. 开火：枪口焰、枪械后坐、枪口光。
2. 飞行：弹道/弹丸轨迹，颜色与武器类型关联。
3. 命中：火花、弹孔/受击材质反馈、短暂受击动画。
4. 特殊：暴击、穿透、连杀、爆炸、燃烧、毒素等独立反馈。
5. 结束：死亡/爆炸/消散，不留下无意义残留物。

性能规则：
- 复用对象池；不在每次开火时持续 new Geometry/Material/Texture。
- 粒子、弹道、飘字有上限和降级档位。
- 低画质减少粒子数量、光源和屏幕空间效果，不改变伤害和命中结果。
- 特效必须在 1、100、300、500 人以及 Boss 战压力场景下实测。

### 3.5 排行榜

排行榜要有“竞技荣誉感”，但信息不能花哨到难以阅读：

- 顶部：Top 1/2/3 三人荣誉展示，第一名视觉最突出。
- 列表：排名、头像/职业、玩家昵称、段位/等级、分数/战绩、本人标识。
- 本人：无论排名是否在当前页，都要有“我的排名”固定入口或定位卡。
- 状态：加载中、空排行榜、网络失败、未登录、刷新中、数据过期。
- 视觉：金/银/铜区分前三，其他名次保持克制；避免每行都发光。
- 适配：窄屏优先保留名次、昵称、分数；次要信息折叠。
- 真实性：不得伪造在线玩家、昵称、头像、分数或全球排行。没有真实后端数据时必须明确标注“本地演示/模拟数据”，不能冒充线上榜单。
- 不擅自改变现有排行 API、数据结构、排序规则、用户身份和反作弊逻辑。

| `fps-shooter` | 按需 | 武器反馈、命中反馈、射击可读性；本项目是自动射击，不应照搬 FPS 操作设计 |
| `game-docs` | 建议 | 维护 GDD、功能索引、设计决策和资源清单 |

注意：上游 three.js 技能文档以较新版本（README 标注 r187）为基准，而本项目规格记录的是 Three.js r149 CDN。**技能只能作为方法参考，不得把 r187 API 代码直接复制进 r149 项目，不得为了使用技能擅自升级引擎。** 如确需升级，必须单独提出兼容性评估、性能基准、迁移计划和回滚方案，等待项目负责人批准。

### 4.2 推荐接入策略

1. 先查看上游 Router、安装说明、技能格式和相关技能的完整 `SKILL.md`。
2. 先使用 `npx skills add gamedev-skills/awesome-gamedev-agent-skills --list` 预览安装内容。
3. 不要在不确认 Agent 环境、Node 版本、安装路径前直接全局安装。
4. 优先将 Router + 美术资产制作 + Web/Three.js + Level Design + Shader 等相关技能用于本项目；其余技能按任务触发。
5. 若 Agent 无法原生读取上游技能，可把本项目真正需要的规则整理为项目内规范，不要未经核对就复制整个上游仓库。
6. 记录上游仓库地址、获取日期、版本/commit、许可证和本地修改。
7. 技能只提供工作方法，不代表自动保证质量；每次产出仍必须经过游戏内截图、资源检查、性能测试和人工审美验收。

## 5. 设计执行流程（任何 Agent 必须遵守）

### 阶段 A：只读盘点

- 读取当前分支、HEAD、工作区状态、目录结构和已有美术报告。
- 截取首页、战斗早/中/后期、Boss、门选择、排行榜、军械库、结算页面。
- 建立“现有资产 → 使用位置 → 运行时加载状态 → 缺陷”清单。
- 对每个需求标记：已完成、部分完成、缺失、需验证。
- 不允许未检查现状就新建重复 UI、重复模型或重复资源。

### 阶段 B：视觉提案

- 先交付一份视觉方向和页面/场景清单。
- 每个主要页面至少提供布局草图/低成本预览或真实游戏截图对比。
- 怪物、枪械、地图先给风格板和资产清单。
- 明确资源规格：格式、尺寸、透明背景、命名、LOD、贴图预算、动画列表。
- 先确认主视觉，再扩展同一资产家族，避免风格漂移。

### 阶段 C：资产制作与集成

- 先做高频资产：士兵/枪械/普通怪/门/UI 图标/战斗特效。
