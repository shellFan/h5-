# V4.1 GLB 士兵集成

## 加载和资源生命周期

`index.html` 加载本地 Three.js r149、同版本 GLTFLoader、SoldierModelLoader 和 SoldierRenderer。GLTFLoader 来自 Three.js 0.149.0 npm 分发包的官方源码，转换为经典脚本闭包以适配现有全局 JS；许可证为 `js/vendor/THREE-LICENSE.txt`。

`js/game.js` 先等待 `SoldierModelLoader.load()`，再构造唯一 Game。等待时显示“正在整备蓝色小队”；GLB 请求或数据验证失败时显示原因与重试按钮，不启动缺失角色的游戏。

加载器缓存 Promise 和解析数据，检查五个网格、共享 PBR 材质、索引、法线、UV、已解码的基础色/ORM 图及 Muzzle 父子关系。两个请求均 settle 后才处置失败加载的部分资源，清空缓存允许重试，避免慢请求在清理后遗留资源。LOD 的重复材质和纹理被释放，完整模型和 LOD 共用同一材质。

运行时资源全部来自 `assets/models/soldier/` 本地 GLB。没有回退至旧球体士兵。`js/models.js` 中三个旧士兵几何工厂已删除，敌人和状态门工厂保留。

## 实例渲染和枪口

`Squad` 保留人数、位置、门效果和战斗属性，委托 `SoldierRenderer` 渲染。每个细节层级五个 InstancedMesh，共两组；每组容量为 500+16。任意时刻只显示一组五个网格，死亡残影占用同组额外槽位，不单独增加角色 DrawCall。

人数 ≤100 使用完整 GLB，>100 使用低模。几何和材质全员共享，实例矩阵动态更新。保留 `squad.mesh`、`legMeshL/R` 供现有调试及测试使用；它们随活动 LOD 切换。

`getShootPositions()` 对选中的士兵触发后坐力，然后使用与 Arms 实例完全相同的矩阵乘以 GLB Muzzle 局部矩阵，返回世界坐标和 shooterIndex。`CombatSystem._fire()` 直接使用该坐标，不再随机偏移弹道起点；目标收敛逻辑继续运行。浏览器测试独立读取实际 Arms instanceMatrix 并校验枪口与新子弹 xyz 一致。

## 六种动画

| 状态 | 实现和触发 |
|---|---|
| Idle | 停止前进时呼吸、轻微头部活动 |
| Run | 左右腿反向 .6 rad 摆动、轻微躯干起伏，每人独立 phase |
| Shoot | 每位射手独立 .16 秒枪械/双臂后坐力，保留跑步基础层 |
| Hit | 减员后存活者 .18 秒受击反应 |
| Death | 被移除角色 .65 秒整体倾倒与收缩；最多保留16个，全部部件一起变换 |
| Victory | 胜利时举枪、呼吸和轻微跳动；结算期间继续更新 |

`squad.setAnimationState(name)` 可用于检视，`null`/Auto 恢复自动状态。reset 清除临时状态、后坐力和死亡残影。暂停时冻结动画和游戏；失败后只继续死亡残影，不推进战斗。

大军团的动作周期以 30Hz 采样，位置和枪口响应仍逐帧更新。不同士兵使用随机错相，射击覆盖层按实际射手触发。

## 阵型和预算

| 人数 | 行列策略 | 横间距 / 纵间距 | 模型比例 | 模型 |
|---|---|---|---:|---|
| 1 | 单兵 | .72 / .72 | 1 | 完整 |
| 12 | 四列三排 | .70 / .72 | 1 | 完整 |
| 31 | 最多七列，平衡行长，浅弧与交错 | .63 / .66 | .86 | 完整 |
| 100 | 最多七列，平衡行长 | .63 / .66 | .86 | 完整 |
| 300 | 最多十一列 | .37 / .50 | .55 | LOD |
| 500 | 最多十三列 | .33 / .46 | .50 | LOD |

行长最多相差一人；小幅稳定个体偏移，队伍半宽按模型肩部包络计算。专项测试覆盖七个人数点，半宽均 ≤2.3，并保留移动/侧门窗口约束。角色动态阴影只在完整模型且人数 ≤64 时开启；场景阴影仍依画质设置。

## 打包、验证和回退

H5 构建清单包含新增加载器、渲染器、GLB、贴图和本地 vendor；修复旧清单漏拷 `js/game.js` 的问题。构建时缺失必要文件或入口脚本会直接失败。`tests/e2e/h5-build.js` 从实际 dist/h5 启动并禁止外网请求，验证可开始游戏。

复现验证：`node tools/v41-verify.js`。截图：`node tools/v41-capture.js`。性能：`node tools/v41-performance.js`。

集成提交：`5e90be2`；动画/枪口：`0c69ab9`；阵型/性能：`daa5714`；构建修复：`b5bb486`；移除旧几何：`a368f52`。回退可按这些阶段使用 git revert，不需要覆盖用户存档或强制推送。

本轮交付面向 H5 浏览器。抖音原生小游戏构建器尚未适配 GLB 的文件/图像加载 API，不能将其产物视为已通过 V4.1 验证；微信/抖音容器、iOS/Android 真机仍需补测。
