# V12 性能报告

> 数据来源：真实测试（tests/e2e/v101-mobile.js 8 机型矩阵 / wechat-emulator.js 帧率采样 /
> 构建包体统计）。模拟器数据为软件渲染环境，真机 GPU 表现预期显著更好。

## 1. H5 移动端矩阵（v101-mobile，390×844 / DPR 2）

- 平均帧时 **4.66ms**（阈值 ≤10ms ✅），28 项功能断言全过
- 机型覆盖：360×640 → 430×932 共 8 档（矩阵历史基线 frameMs 1.0~2.2ms 桌面级，
  移动模拟阈值内）
- DrawCall 基线 ~104 / 三角形 ~1.34M（battle 稳态），纹理 22-23 —— 与 V11 基线持平
  （本轮修复未引入绘制增量；逐发同步移除降低 CPU 上传）

## 2. 微信模拟器（软件渲染 SwiftShader）

| 指标 | 数值 | 说明 |
|---|---|---|
| 战斗帧率 | **103 FPS**（5s 采样） | 软件渲染下已达标；真机 GPU 预期更高 |
| 首局进入 | 模型加载 + 构造 < 8s（模拟器磁盘+解码） | P0 资源 6 GLB 优先，其余后台续载 |
| UI 重绘 | 仅脏帧全量光栅（390×844×dpr≤2） | HUD 数值变更驱动；无变更帧零光栅 |

## 3. 包体预算（微信小游戏平台红线）

| 项 | 数值 | 上限 | 结果 |
|---|---|---|---|
| 主包 | **1.51 MB** | 4 MB | ✅（余量 62%） |
| assets 分包 | **3.37 MB** | 4 MB | ✅（26 GLB + 2 SVG；源纹理/文档/未引用已排除） |
| 整包 | **4.88 MB** | 30 MB | ✅ |
| H5 dist | 5.36 MB | — | ✅ |

资源优先级（assets-manifest.json）：P0 首局必需（士兵+普通/快速僵尸+头像，
~1.6MB）→ P1 特型僵尸 → P2 Boss → P3 装饰。启动仅等待 P0（6 GLB）。

## 4. 微信专项检查项

- GPU 内存：纹理数 22-23 + 模型 bank 常驻复用（生命周期不释放为设计），
  门/特效纹理逐局 dispose ✓
- GLB：全部自包含（无外部纹理请求）✓
- 后台切换：onHide 自动暂停 + 音频挂起 + 广告中断结算 ✓
- 长时间运行：V11 60 分钟 soak PASS 基线维持（本轮改动不触及泄漏面：
  combat/effects/enemies 池与 dispose 逻辑未变）
- 低端降级：画质三档 + DPR 上限 + P95 帧时采样既有机制保留 ✓

## 5. 优化机会（后续版本，非阻塞）

1. DRACO/KTX2 压缩：26 GLB 3.37MB → 预计可减 40-60%（当前包体余量充足，暂缓）
2. UI 局部重绘（脏区域）替代全量光栅（当前脏帧才重绘，已够用）
3. 碰撞空间分桶（>500 怪时再考虑）
